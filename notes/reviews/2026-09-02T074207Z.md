## MODERATE 1 — rung 2a's earliest-phrase rule traps on a leading `"Answer:"` header and returns a sentence fragment

`src/quantartifact/scoring/extract.py:416-436`

**First, to answer the question you asked: the initialisation and sentinel logic are correct, and there is no off-by-one.** `best_position = len(text) + 1` exceeds any possible `find()` result, so the first hit always wins the comparison. `best_end = -1` cannot collide with a real value, since `best_end = position + len(phrase)` with `position >= 0` and every phrase non-empty gives `best_end >= 1`. And the `position >= 0` guard is load-bearing rather than decorative: without it, `find()`'s `-1` would satisfy `-1 < best_position` and set `best_end = len(phrase) - 1`, a plausible-looking garbage offset. It is present. Empty text and a phrase at position 0 both behave correctly.

**The defect is in the rule, not the arithmetic.** `_COMMITMENT_PHRASES` contains the bare `"answer:"`, which for rung 2's *latest*-match rule is a reasonable commitment marker and for rung 2a's *earliest*-match rule is a **header trap**.

Traced analytically on `"Answer: Let me compute. 3+4=7. So the answer is 7"`:

- `"answer:"` finds at 0; `"the answer is"` finds at 34. Earliest wins, so `best_end = 7`.
- `tail = "Let me compute. 3+4=7. So the answer is 7"`.
- The sentence split `(?<=[0-9A-Za-z\)\}])\.(?:\s|$)` fires on the period after `compute`.
- **Rung 2a returns `"Let me compute"`.** Rung 2, taking the latest phrase, returns `"7"`.

So on a generation shaped like a chat model's `"Answer: <reasoning> ... the answer is N"`, rung 2a extracts a mid-sentence fragment where rung 2 extracts the answer. That is not a subtle mis-selection; it is a non-answer.

**Why it is latent rather than live, and why it will not stay latent.** Rung 2a currently has no consumer (MODERATE 2), and on `gsm8k` the `hash_marker` rule fires before the phrase rule and rescues it. Your own fixture at `tests/test_extract.py:523`, `"Final Answer: Jean can fill 14 bags of lollipops.\n#### 14"`, contains exactly this header and passes **only because `####` takes precedence**. On `bbh` and `arc_challenge_chat` there is no hash marker, so the phrase rule runs unprotected, and no fixture covers a leading header without a `####`.

**Confirmed by:** analytic trace against the phrase tuple and the split regex; I could not execute it, since only `pytest` and `ruff` are permitted in this session. Worth your own one-line check before acting.

**Fix.** Give rung 2a its own anchor tuple that excludes the bare `"answer:"` header form, and say in a comment why the two rungs use different sets: under a latest-match rule a header is harmless because a later phrase supersedes it, and under an earliest-match rule it is the first thing found. Alternatively, on a tie of position prefer the longest phrase, which fixes `"final answer:"` but not a standalone `"Answer:"`.

**On your ordering question, the answer is stronger than "defensible": it is load-bearing and right, for a reason you did not state.** For `gsm8k`, rung 1's strict pattern is `#### (\-?[0-9\.\,]+)` applied with `group_select=0`, i.e. the **first** `####`. Rung 2a's `hash_marker` rule is `_apply_harness_regex(r"####\s*(.+)", t, 0)` — also the first match. So putting `hash_marker` ahead of the phrase makes rung 2a's selection **coincide with rung 1's on the hash-marker task**, which is exactly the monotonicity property rung 2a exists to have. It also happens to be what makes your two class-A cases recover. On `"The answer is 42. Let me redo: #### 7"` the ordering yields 7 rather than 42, which differs from a literal "first commitment" reading but agrees with rung 1, and agreeing with rung 1 is the property that matters. The docstring should say "the strongest marker, else the first commitment phrase" rather than "the first commitment", so the invariant it advertises is the one it has.

## MODERATE 3 — `holm_block` reintroduces the vacuous-truth shape through its non-empty path

`scripts/analyze_run.py:148-152`

```python
if effects:
    rows = [... for r in holm_bonferroni(effects, family=family)]
    return {"family": family, "m": rows[0]["m"], "status": "corrected", "rows": rows}
return {"family": family, "m": 0, "status": absent_reason, "rows": []}
```

**Why it is wrong.** `m` is read from `rows[0]["m"]`, and `holm_bonferroni` sets `m` to the count of effects that **have p-values**, not the count of effects. So a family that is non-empty but entirely untested takes the `if effects` branch and returns `status: "corrected"` with `m: 0`.

**How it fails.** Concretely and via a documented flag: `analyze_run.py --task arc_challenge_chat`. Every ARC H3 effect has `p_value: null`, because `mcnemar_exact` returns `None` when there are no discordant pairs and ARC has none by construction — that is the same degeneracy R25.1 was raised about, confirmed in the committed `analysis_pilot-v2.json`. So `h3` is non-empty, `m` is 0, `status` is `"corrected"`, and the report asserts that a Holm correction was performed over a family in which nothing was testable. **That is the shape `holm_block` was written to eliminate**, surviving on the other side of the branch.

Secondarily, `absent_reason` is free text with no validation, so a caller can pass `"corrected"` and make the two cases indistinguishable. `m: 0` would still disambiguate, which is why this half is minor — but the point of `status` is that it cannot lie, and a free-text field can.

**Confirmed by:** reading, plus the previously verified `p_value: null` on the ARC effects in the committed artifact.

**Fix.** Compute the status from `m` rather than from emptiness: `status = "corrected" if m else "no testable effects (none carried a p-value)"`, and make `status` a closed set of literals rather than a caller-supplied string. That collapses both halves into one change and removes the last place a caller can choose the status.

## MODERATE 4 — `recovered`/`destroyed` are labelled noise class 2, but §9f's table names them class 1

`src/quantartifact/analysis/interaction.py:632`

**To answer your question directly: the Wilson interval and the shared denominator are both right; the noise class is the part I would question.**

The interval is correct. Each direction is a rate of a binary event over `n` items, so a single-proportion Wilson interval is the right instrument, and it is the right *choice* of instrument given the counts involved: `destroyed` is 0 to 3 per arm, where the normal approximation would give a negative lower bound and Wilson gives `[0, z²/(n+z²)]` at a count of zero.

The shared denominator is correct, and I checked the consequence you were relying on rather than just the arithmetic: `recovered` and `destroyed` are disjoint subsets of the same `cell.items`, so `recovered/n − destroyed/n = (recovered − destroyed)/n`, which is exactly what `rung_mcnemar` reports as the net over the same item set with the same `b`/`c` definitions. The two functions will agree, which is the property that makes the decomposition auditable against the companion.

**The class assignment is where I disagree, and it is a science question rather than a code defect.** §9f's class-1 row reads: *"anything computed by re-scoring **one fixed set** of generations: rung monotonicity, compliance labels, §8's trace scan, the found/committed split, **per-item rung agreement** — exactly zero, no boundary crossed."* `destroyed` is per-item rung agreement over one arm's fixed generation set, computed by re-scoring. Class 2 is defined as *"a **within-arm difference** of two rungs"*, and the net gap is that difference; `destroyed` on its own is not a difference, so nothing cancels.

So my reading is that the **net** is class 2 and the two **components** are class 1. **The direction is conservative** — class 2 carries a larger floor than class 1, so labelling `destroyed` class 2 makes a destruction claim harder to make, not easier. That is why this is a flag rather than a stop. But §9f's taxonomy is registered and the floor an effect binds to follows from it, so this is the planner's to settle, not mine and not the code's. Record it as asked rather than as decided.
